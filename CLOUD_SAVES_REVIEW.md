# Проверка облачных сохранений

Разработка в PR #1, production и Worker не изменялись.
server/worker.mjs подготовлен из предоставленного файла обновления. worker_backup.js содержит только старый webhook; он не подтверждает актуальный код production. Нельзя считать предложенный файл точной копией работающего Worker.

## Реализовано

- Локальная копия сохраняется; перед ручной заменой создаётся отдельная резервная копия.
- Последний подтверждённый облаком снимок и revision запоминаются. Если облако не менялось, повторный выбор не требуется. Изменение облака другим устройством требует выбора, без сравнения монет.
- Запросы записи сериализованы. Новая очередь не заменяется старым снимком при ошибке. Конфликт блокирует записи до повторного чтения и выбора.
- В кандидате Worker исправлено включение signature в HMAC-проверку через токен. Дубликаты полей и просроченные initData отклоняются; ID берётся из проверенного user.
- Параметризованный SQL с проверкой revision; ограничение размера потокового тела и базовая проверка структуры сохранения. Существующие записи не удаляются.
- Подготовлены /start, отдельный /help и ответ на обычный текст. Только личные чаты. Ограничение частоты и повторов в памяти одного isolate: это не распределённая защита и не гарантия однократной доставки.

## Проверки

node --test tests/worker.test.mjs: подпись с signature, подмена, отсутствие авторизации, неверный формат, разделение пользователей, конфликт revision, сохранение нулевых монет после престижа, секрет webhook и ответ с кнопкой.
node --check cloud-saves.js; node --check server/worker.mjs.
Браузер: tests/cloud-browser.cjs (Playwright + Edge, PLAYWRIGHT_MODULE может указывать на установленный модуль). Чистый запуск, имитация API, конфликт, пауза записи, ручное восстановление, повторный запуск без диалога.
Это локальные проверки с подменой внешних сервисов, не настоящая D1/Telegram-синхронизация.

## Оставшиеся риски

Экономика, кристаллы, премиум и прогресс управляются клиентом. Авторизованный игрок может изменить собственное сохранение. Проверка формата не является античитом. Нельзя использовать эти поля как основание для платных ресурсов или доверенного рейтинга.
Минимальная будущая защита: отдельный серверный баланс покупок, серверный каталог цен, создание заказа сервером, проверка successful_payment и уникальности telegram_payment_charge_id с атомарным начислением. Не начислять по invoiceClosed или клиентскому флагу. До отдельной реализации реальные Stars-покупки не включать.
Серверный рейтинг должен принимать подтверждённые сервером события, а не произвольный total из сохранения. Переписывание экономики не выполнялось.
Старые chunk-сохранения Telegram не импортируются автоматически. Не очищать их и локальные данные.
Локальные резервные копии требуют места; ошибка создания копии останавливает замену. Синхронизация зависит от доступности браузерного хранилища.
Активная сессия initData ограничена 24 часами; при 401 нужно переоткрыть Mini App.

## До публикации

1. Получить актуальный экспорт работающего Worker и подтвердить схему D1, не передавая секреты в чат.
2. Развернуть отдельный тестовый Worker/D1 и тестовую Mini App; направить тестовый frontend на этот API. Не использовать сохранения игроков.
3. На согласованном тестовом аккаунте проверить перенос существующей локальной версии, восстановление на втором устройстве, офлайн-изменения, возвращение сети, одновременную игру, престиж, перезапуск и сохранность резервной копии. Проверить Android и iOS.
4. Проверить /start, /help, обычный текст, повтор webhook и ошибку Telegram API на тестовом боте.
5. Только после результатов и подтверждения владельца обновлять production. Откат frontend не откатывает D1; таблицу сохранений не очищать.

Источники: https://core.telegram.org/bots/webapps#validating-data-received-via-the-mini-app и https://core.telegram.org/bots/payments-stars .

Проверка истории всех доступных Git refs и текущих файлов по шаблонам bot token, GitHub token и private key: совпадений нет. Это ограниченный поиск шаблонов, не гарантия отсутствия всех секретов. 29 встроенных скриптов index.html разобраны без синтаксических ошибок.
Браузерный тест дополнительно проверяет ошибку сети и последующую запись состояния с увеличенным resets и нулевыми монетами. Само нажатие кнопки престижа в этой проверке не эмулируется.
